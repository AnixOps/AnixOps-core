# config-core

`config-core` contains the first pure configuration and subscription parsing services for the unified network control kernel.

The crate implements `ConfigurationService` for a minimal TOML document shape with `schema_version`, `profile`, `profiles`, `listeners`, `nodes`, and `routes` fields. It normalizes profiles, inbound listeners, local nodes, and default route sets into `ConfigSnapshot` without reading files, making network requests, starting proxy engines, or depending on platform adapters.

The crate also implements `SubscriptionService` as `CoreSubscriptionService`. It accepts explicit `inline:` subscription sources, parses the same minimal TOML `nodes` and `routes` subset, single `ss://`, `trojan://`, `vless://`, `vmess://`, `hysteria2://`/`hy2://`, and `tuic://` URLs, Clash YAML `proxies` catalog imports, sing-box JSON `outbounds` catalog imports, Surge proxy line catalog imports, Loon proxy line catalog imports, Quantumult X proxy/server line catalog imports, plaintext proxy link lists, and base64 encoded proxy link lists into `SubscriptionDocument`, and normalizes them into `NodeCatalog`. Hysteria2 retains the share-link password, port hopping, supported obfuscation, and TLS metadata; TUIC retains UUID, optional password, congestion control, and TLS metadata. Remote subscription fetching, file loading, authentication, DNS, plugin, duplicate-id, and listener/node graph validation remain out of scope for this crate; secrets are only carried as node metadata for adapter translation and must not be echoed in diagnostics.

Every format except the first-party TOML reads its entries one by one. An entry that cannot be read (a proxy type the reader does not know, a missing or mistyped field, a bad port, a malformed share link) is skipped with a `Warning` diagnostic in `SubscriptionDocument.diagnostics` that keeps the entry's own error code and names it by format, position, and its name and type when they read as labels, never by its text or credentials; the other entries still import. Only when no node is left does parsing fail, with the first skipped entry's error. Built-in policy entries (Surge and Loon `Name = direct` / `reject*`, Clash `type: direct` / `reject` / `dns`, Quantumult X `direct` / `reject`) are not nodes and are skipped silently; imported rules and policy groups that name them route as `DIRECT` or the matching `REJECT` kind. Loon and Surge share `[Proxy]`: the first field after the port decides the style, and a quoted value or a base64 value with `=` padding is a Loon positional password, not a Surge option.

Clash YAML, Surge, Loon and Quantumult X vmess, VLESS and Trojan proxies keep their TLS (`tls`/`over-tls`, SNI, skip-cert-verify, ALPN, uTLS fingerprint), REALITY (public key, short id), flow and transport (`ws`, `grpc`, `h2`, HTTPUpgrade, XHTTP with path, host and service name) options: each reader spells them as the fields of the equivalent share link and writes them through the share-link mapping, so the node imports as the same outbound as that link. An option no node field can carry (HTTP/1.1 header obfuscation, an unknown transport, ECH, unknown XHTTP settings) is written as `proxy.unsupported_option` with a fixed code, and the node importer reports the node as unsupported instead of running it without that option. Shadowsocks SIP003 plugins from every format (share-link `?plugin=`, Clash and sing-box `plugin`, Surge and Quantumult X `obfs=`, Surge and Loon ShadowTLS, Loon `obfs-name=`) are recorded by name only as `shadowsocks.plugin`; the engine implements no plugin, so those nodes are reported unsupported rather than run as plain Shadowsocks. The full field table is in `docs/architecture/subscription-url-to-sing-box-run-source-contract.md`.

Every node read from a subscription format other than the TOML subset (which carries its own ids) gets a stable id from the `node_id` module: `{protocol}-{host}-{port}-{endpoint hash}`, where the SHA-256 endpoint hash covers the protocol, exact host and port, transport (type, path, host, service name), TLS server name and the endpoint of the node it connects through. Nodes that share that base but use different credentials get a `-{credential hash}` suffix; entries that are identical in every respect get `-2`, `-3`. Ids never depend on the entry's name or position, so reordering, inserting or renaming entries keeps every other node's id, and they never contain a secret. The id earlier releases gave the node (its name made ASCII plus a position-dependent suffix) is kept as `subscription.legacy_id` metadata; `node_id::find_node` looks a saved selection up by the current id and then by that previous id. See `docs/architecture/subscription-node-ids.md`.

Certificate pins are kept for every format that writes them: share-link `pinSHA256` (Hysteria2) and `pcs` (V2Ray family), sing-box `certificate_sha256` and `certificate_public_key_sha256`, Clash `fingerprint`, Surge `server-cert-fingerprint-sha256`, and Loon and Quantumult X `tls-cert-sha256` and `tls-pubkey-sha256`. Digests of the whole certificate go to `tls.certificate_sha256` as comma-separated lowercase hex, digests of its public key to `tls.certificate_public_key_sha256` as comma-separated standard base64 (`certificate_pin` parses both spellings); a value that is not a SHA-256 digest is kept as written so the importer can refuse the node. Catalogs saved before `tls.certificate_sha256` existed hold certificate digests in hex under `tls.certificate_public_key_sha256`, and readers take hex there as a certificate pin.

`networkcore-linux run-url`, the desktop GUIs and the iOS importer turn the normalized catalog into embedded-engine outbounds; the retained V2Ray-family TLS/REALITY/uTLS/transport fields carry through. Hysteria2 and TUIC URL parser gates are catalog import only as far as MITM goes: their foreground path does not enable HTTP/3 MITM. Parsing does not infer unsupported XHTTP, ECH or multiplex fields. Clash YAML, sing-box JSON, Surge, Loon and Quantumult X nodes reach the same outbounds as share links (see below). `networkcore-linux start` consumes normalized local configuration through the runtime and native engine path; persisted subscription catalogs are not yet wired into generic runtime startup.

The `routing` module models first-class rules (`DOMAIN`, `DOMAIN-SUFFIX`, `IP-CIDR`/`IP-CIDR6`, `GEOIP`, `FINAL`) and `select`/`url-test`/`fallback` policy groups. A configuration with top-level `rules` and `[[policy_groups]]` produces `ParsedConfigDocument.routing`. `RoutingModel::decide` is the in-process decision interface for `engine-embedded`; GeoIP, DNS, selection, and health results come from a caller-supplied `RoutingEnvironment`. See `docs/architecture/routing-policy-group-model.md` and the shared snapshot fixture in `testdata/routing-snapshot/`.

Verification for this crate is performed only by GitHub Actions, following the repository CI/CD policy.
