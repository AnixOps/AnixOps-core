# 组网端到端实验床

各线程已有模块单元测试与进程内集成测试；本实验床用真实拓扑验收组网程序 `anixops-mesh`，是内核 0.4、0.5 打候选版（RC）前的必过项（见 [发布策略](release-strategy.md)「候选版（RC）流程」）。需求编号见 [组网内核需求](mesh-requirements.md) 与项目需求表。

## 原理

- 每台机器是一个 Linux 网络命名空间；底层网段（代替站点之间的公网）是交换命名空间里的网桥，机器经 veth 接入，可用 netem 加延迟与丢包；网关后面的局域网是网关与局域网主机之间的 veth。
- 节点就是 CI 构建的 `anixops-mesh run`，每个命名空间一个进程，配置格式见 [组网模块设计](architecture/mesh-module.md)「配置」。实验床只搭线、启动程序，并从外部观察：ping、标准输出的状态行、退出码与 stderr 最后一行 JSON。不模拟任何组网行为。
- 底层地址用 198.18.0.0/15（基准测试保留段，不在内网白名单内，节点不会把它当作重叠网段）；区域虚拟网段 10.144.1.0/24；局域网 192.168.10.0/24。
- 每个场景新建一套命名空间，结束即删除，场景之间互不影响。失败时打印全部节点的标准输出与 stderr。
- 代码：[`.github/scripts/mesh-e2e/`](../.github/scripts/mesh-e2e/)（`lab.py` 实验床，`scenarios.py` 场景与登记表）。只用 Python 标准库与 `ip`、`ping`、`tc`、`sysctl`、`openssl`。

## 运行位置与触发

- 工作流 [`mesh-e2e.yml`](../.github/workflows/mesh-e2e.yml)，跑在 GitHub 托管的 `ubuntu-24.04` 上。本仓库是公开仓库，按项目规则公开仓库不用自托管 runner（fork 的拉取请求可以在自托管机器上执行任意代码）；托管 runner 对公开仓库不计费，且有免密 sudo，可以创建命名空间。
- 按改动范围触发：`apps/mesh-node/**`、`crates/outbound-mesh/**`、`crates/engine-outbound/**`、`Cargo.lock`、`Cargo.toml`、实验床脚本、本文与工作流自身。另在 `v*` 标签、手动触发与每日定时运行；定时与手动可设重复轮数（默认定时 3 轮），用来发现偶发失败。
- 专线骨干（ANX-Line）属于闭源构建，不能进公开仓库的 CI。需要专线的场景（P01–P03 的专线形态）在 anx 私有仓库运行：anx 以 cargo 依赖引用本仓库，复用本目录的实验床，专线二进制取自 anx 自己的构建，跑在 pve 自托管 runner 上（遵守 anx 的 50 GB 缓存上限）。本仓库的 P01–P03 只在开源构建有骨干链路实现（规范 §17.3 的可选开源回落）时验证选路与绕行；没有时这三项只在 anx 运行，并在 RC 清单中按 anx 的结果判定。

## 场景

状态只有两种：「启用」的场景每次都跑，任何失败都让工作流失败；「待启用」的场景依赖的功能尚未合并，结果文件中列为 pending，不计为通过。功能合并后由本线程把场景改为启用，断言不因启用而放宽。`scenarios.py --check-docs` 在每次运行时核对下表与登记表的编号、需求与状态，不一致即失败。

| 编号 | 场景 | 需求 | 状态 | 说明 |
|---|---|---|---|---|
| E01 | 同区两完整节点经 TCP 直连互访（安全模式） | R2、R3、R30 | 启用 | 区域网络（`kind = managed`），成员公钥清单含双方 |
| E02 | 同区两完整节点经 UDP 直连互访（安全模式） | R2、R3、R30 | 启用 | 同 E01，对端走 UDP |
| E03 | 底层不通的两节点经完整节点中转互访 | R7、R10 | 启用 | B、C 在不同底层网段，只有 A 同时接入两段 |
| E04 | 关闭中转的完整节点只作目的、不替他人转发 | R10 | 启用 | E03 拓扑，A 设 `relay: false`：B、C 仍能到 A，B、C 之间不通 |
| E05 | 接入节点经完整节点入网，且不能监听 | R10 | 启用 | 接入节点到达全部成员；带 `listen` 的接入节点配置退出码 2 |
| E06 | 完整节点通告局域网子网，远端节点经组网访问局域网主机 | R10、R17 | 启用 | 远端状态行 `system_routes` 含该网段后 ping 局域网主机。Linux 节点尚未自行开启主机转发（设计文档中 Linux 输出 `off`），由实验床在网关命名空间开启；Linux 子网路由合并后改为断言节点自己开启 |
| E07 | 通告公网网段的配置被拒绝 | R5、R17 | 启用 | 退出码 2，`{"error":"config"}` |
| E08 | 网络密钥不同的节点无法入网 | R2、R30 | 启用 | 双向 15 秒无应答，错误密钥一方状态无邻居；同时有一个密钥正确的对照节点能到达 A |
| E09 | 不在成员公钥清单中的节点被拒并在状态中标出 | R30 | 启用 | 被拒节点无法到达任何成员；A 的状态行 `not_native` 非空（规范 §8.3.1） |
| E10 | 端口或虚拟网卡被占用时拒绝启动并给出冲突原因 | R12 | 启用 | 退出码 3，stderr 最后一行 `{"error":"conflict","conflict":"port_in_use"}` 与 `tun_in_use`；已运行的节点不受影响 |
| E11 | 旧网（默认模式）中我方节点互访 | R2 | 启用 | `kind = legacy`、`secure_mode = false`、`aes-gcm` |
| E12 | 未加密网络须显式选择，未选择的节点丢弃明文流量 | R14 | 启用 | 显式 `cipher: none` 的两节点互通；未选择的第三个节点 15 秒无应答 |
| P01 | 两地区各两台边界节点经骨干互联，跨地区互访 | R18、R19、R22 | 待启用 | 等骨干与边界节点（core #342）和区域迁区线程；拓扑见下文 |
| P02 | 一台边界节点下线后跨地区流量改走同区另一台边界节点 | R19 | 待启用 | 同 P01 |
| P03 | 地区间直连劣化时经第三地区绕行，恢复后切回 | R19 | 待启用 | 同 P01，另需测量与绕行；netem 制造劣化 |
| P04 | 宿主组网关通告组地址段，网关下线后改走备用网关 | R21、R25 | 待启用 | 等宿主组运行时（`host_groups`） |
| P05 | 旧版节点与我方节点黑盒互通（两种模式） | R1、R2 | 待启用 | 等 M3 黑盒互通与仓库变量 `MESH_PEER_URL`、`MESH_PEER_SHA256`（[人工介入](manual-intervention.md)） |
| P06 | 旧版节点留在旧网，经我方桥接节点访问区域网络 | R1、R30 | 待启用 | 等 P05 与桥接迁移（规范 §15.11）；旧版节点不得加入区域网络 |
| P07 | 自定义路径：全为我方途经点时严格按路径转发 | R8 | 待启用 | 等自定义路径接入驱动（#346 为第一部分）；按途经点底层网卡字节数判断实际路径 |
| P08 | 自定义路径途经点不可达时回落默认路由并报告 | R9 | 待启用 | 同 P07 |
| P09 | 外部网络桥接：白名单成员经桥接节点访问外部网段，其余被丢弃 | R36 | 待启用 | 等外部网络桥接运行时（Linux 完整节点） |
| P10 | 内网域名：节点按后缀本机应答成员名字 | R28 | 待启用 | 等独立节点的固定解析地址（`dns.resolver_address`，内核 0.4） |
| P11 | OpenWrt 设备（QEMU）安装软件包后入网并通告局域网 | R32、R35 | 待启用 | 等 OpenWrt 镜像接入实验床（QEMU，KVM 不可用时用软件模拟） |

### 0.4 目标拓扑（P01–P04、P06、P09）

```text
 地区 eu（10.144.1.0/24）                 地区 ap（10.144.2.0/24）
   成员 e1 ── 边界 eb1 ═══╗       ╔═══ 边界 ab1 ── 成员 a1
          └── 边界 eb2 ═══╬═骨干══╬═══ 边界 ab2 ──┘
                          ╚═══════╝
   宿主组 172.20.0.0/24：网关 e1、备用网关 eb2，组内主机 vm1
   旧网 legacy：旧版节点 old1 ── 我方桥接节点 br1（同时在 eu）
   外部网络 172.30.0.0/24：桥接节点 eb1 的外部网卡（routes 不得落在 100.64.0.0/10 内，规范 §15.12）
   自定义路径：e1 → a1 经 eb2（eb2 下线后回落并报告）
```

每条骨干链路是两地区边界节点之间独立的底层网段，netem 可单独控制每条链路的延迟与丢包。

## 本地运行

需要 root。先构建节点程序（CI 之外仅供排查）：

```sh
cargo build --release -p mesh-node --bin anixops-mesh
sudo python3 .github/scripts/mesh-e2e/scenarios.py --binary target/release/anixops-mesh --only E01,E03
python3 .github/scripts/mesh-e2e/scenarios.py --list
```

`--repeat N` 重复全部选中场景 N 轮；`--results F` 写出 JSON 结果（含待启用场景及其等待项）；`--keep` 保留配置与日志目录。

## 完成标准

- 工作流合并到 `main`，定时运行连续多轮无偶发失败。
- 项目需求表各条的审计列引用对应场景编号。
- 内核 0.4 RC 清单把「组网端到端」列为必过项；某场景仍为待启用时，对应功能在发布说明中标为未启用。
