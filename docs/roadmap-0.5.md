# 发展路线：内核 0.3 → 0.5（客户端 1.1 → 1.3）

本文是内核（本仓库 AnixOps-core）、客户端（[AnixOps/anixops-net](https://github.com/AnixOps/anixops-net)）与 ANX 三条线到 **内核 0.5.0 / 客户端 1.3** 为止的统一路线。客户端仓库只链接本文，不另写副本；ANX 是闭源仓库，本文只写它对外的交付边界（`anx-node` / `anx-server` 进程与能力名），内部排期写在 ANX 仓库的改进项文档里。

- 制定日期：2026-11-28。现状以当天 `main` 为准。
- 需求编号 R1–R36 是组网需求（内核职责见 [mesh-requirements.md](mesh-requirements.md)，客户端职责见客户端仓库 `docs/mesh-requirements.md`）。
- 版本节奏、候选版与维护分支见 [release-strategy.md](release-strategy.md)，各版本承诺不变的接口见 [compatibility-surface.md](compatibility-surface.md)。
- 本文与 [ROADMAP.md](../ROADMAP.md) 的 P0–P4 历史阶段不冲突：P0–P4 记录 0.2.0 及以前的交付，本文接管 0.3 起的版本规划。

代理协议、MITM 与规则等非组网能力不设版本目标，按小版本与补丁照常推进，同样遵守第 2 节的规则；本文第 4、5 节里列出的平台对齐项（节点体检、Fake-IP、应用内更新、命令行工具、防泄漏开关）是按版本排入的建议，维护者可调整。

客户端版本号独立，每份客户端发布说明写明所带的内核版本。ANX 不单独编号对外版本，跟随内核小版本交付 `anx-node`。

## 2. 贯穿各版本的规则

1. **质量第一。** 不为赶进度放宽测试、门槛或审计结论；做不到的写进 [manual-intervention.md](manual-intervention.md) 并告知维护者。
2. **默认关闭，审计后打开。** 0.4/0.5 的功能已有代码合入 `main`，但每项都在 `anixcore` 的默认关闭开关后面（`crates/node-runtime/src/config.rs`）：`mesh_regions`、`mesh_host_groups`、`mesh_backbone`、`mesh_external_bridge`、`mesh_paths`；节点设置 `node.waypoint_relay` 缺省也为 false。开关关闭时不声明能力，`PUT /v1/mesh` 带对应配置段整份返回 400（`*_disabled`）。某个小版本要交付一项功能，先过独立审计，再在该版本里把开关改为默认开启；新增的 0.4/0.5 能力或配置段，必须先有默认关闭开关、400 拒绝与测试才能合入。
3. **每条需求三栏收口。** 每个 R 编号都要有结论、成果、审计三栏（需求文档的规则）；PR 合并后交给独立审计，审计未通过的项不算完成。
4. **发布节奏。** 冻结时从 `main` 切 `release/X.Y`，先出 RC（脱敏的上版配置加载、启动、连接、回退验收，各平台客户端固定 RC 提交验收），再出正式版；补丁版只收修复，安全修复可单独发版。0.4 起每次发布要求同一提交的 `Mesh end-to-end` 成功。打 tag、发布、TestFlight 上传都要维护者明确同意。
5. **功能版本发布后由维护者另行安排第三方审计，下一个版本修复审计发现。**
6. **公开版不带预设分流规则或插件**；内置下载表只有 geoip-cn 与 geosite-cn（[no-presets.md](no-presets.md)）。
7. **组网只限内网**：流量只进虚拟网段与对端通告的子网，不作公网出口（边界节点之间的骨干转发是唯一例外，且只转发组网流量）。
8. **分发范围**：代理客户端不在中国大陆分发；组网、地区中继与合作方的大陆网络照常推进。
9. **文本中立**：公开文档、界面、发布说明不出现第三方组网程序、第三方内核或同类产品的名字（兼容说明写“兼容常见规则语法”）。

### 3.3 客户端 1.1.0

- 固定内核 `v0.3.1`，不固定 `main`（`main` 含 0.4 代码）。
- 打开组网发布闸门：`client-core` 的 `mesh::ENABLED` 与 Apple 端 `MeshSupport.enabled` 同时打开；带闸门的构建只对内核 ≥ 0.3.0-rc.2 发送 `"allow_mesh": true`，以 `capabilities.mesh` 判断是否可用，不看 `feature_set_version`。
- 组网界面 1.1 范围：R6/R16 成员、子网视图（路径、延迟、跳数、重叠标注）；R14 未加密网络默认拒绝、显式选择后标「未加密」；R17 公网网段标出并建议确认；R23 组网与代理开关独立，手机共用同一 VPN；R28 内网域名可复制、重名标记；R29 「地址未受管」提示；R31 部分（填入入网凭据）。
- 平台缺口：Linux「只开组网」与「解析内网域名」（目前 ❌）、Windows 内网域名依赖 NRPT 的限制写进说明。
- 发布前：各平台真机验收（Windows、macOS、Linux、Android、iOS TestFlight），每个 TestFlight 构建回答出口合规问题。

## 6. ANX 对外交付边界（随内核版本）

ANX 只以独立的 `anx-node` / `anx-server` 进程交付，经 gRPC、HTTP 管理接口、配置文件与命令行驱动，不以库形式进入其他仓库。对外可见的只有公开边界文件里的字段、命令行参数、指标名、错误码与能力名。

| 内核版本 | `anx-node` 交付 |
|---|---|
| 0.3.x | 跟随内核 0.3 的组网能力（与 `anixcore` 相同的默认能力集） |
| 0.4 | 内置组网节点并支持骨干（`with_backbone` 由配置决定）；区域间骨干链路实现及其计数器经管理接口导出；公开边界文件补 0.4 能力名 |
| 0.5 | 跟随自定义路径与途经中转；其余排期见 ANX 仓库改进项文档 |
