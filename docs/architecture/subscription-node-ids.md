# 订阅节点的稳定 id

本文件说明订阅导入时节点 id 的生成规则、旧 id 的迁移方式，以及客户端需要配合的事项。实现在 `crates/config-core/src/node_id.rs`，合同测试在 `crates/config-core/tests/node_id_contracts.rs`。

## 为什么要稳定

客户端按节点 id 记住用户选中的节点和策略组里选中的成员，订阅刷新后按同一个 id 继承选择。所以 id 必须一直指向同一台服务器：机场调整顺序、增删节点、改名，都不能让某个 id 变成另一个节点。

1.0.0 之前的 id 是 `{格式}-{协议}-{ASCII 化的名称}`，重复时加 `-{已出现的 id 数 + 1}`：

- 非 ASCII 字符全部变成 `-`，「🇭🇰 香港 01」和「🇯🇵 日本 01」都是 `clash-ss-01`，纯中文名都是 `clash-ss-node`；
- 后缀取决于节点在列表里的位置。

结果是机场在前面插入一个节点后，`clash-ss-01-2` 从「日本 01」变成「香港 01」，客户端不提示就把出口换到另一个地区。

## 规则

只对订阅格式（分享链接、Clash YAML、sing-box JSON、Surge、Loon、Quantumult X）生成；内核 TOML 配置里的节点自带 id，不受影响。

1. **基础 id**：`{协议}-{主机}-{端口}-{端点哈希}`。
   - 协议：`ss`、`vmess`、`vless`、`trojan`、`hysteria2`、`tuic`、`wireguard`、`mieru`、`snell`、`iwan`、`anx`、`http`、`socks` 等，与来源格式无关。
   - 主机：只为可读，ASCII 小写化、非字母数字变 `-`，最多 40 个字符。
   - 端点哈希：SHA-256 的前 10 个十六进制字符，覆盖协议、原样的主机（小写）、端口、传输（`v2ray.transport.type`/`host`/`path`/`service_name`、`mieru.transport`）、TLS 服务器名（`tls.server_name`、`anx.server_name`），以及链式节点所经节点的端点哈希（按名字找到第一个同名节点，与 `via` 解析一致；最多跟 8 层）。
2. **凭据后缀**：只有基础 id 相同、凭据不同的节点才加 `-{凭据哈希}`（SHA-256 前 8 个十六进制字符，输入是端点哈希加各协议的凭据字段）。id 里从不出现凭据本身。
3. **重复后缀**：各方面都相同的条目（只有名字不同）按出现顺序加 `-2`、`-3`。它们连到同一台服务器、用同一份凭据，谁拿哪个编号不影响流量去向。

性质：

- 名字和位置不参与，所以重排、插入、删除、改名都不改变其他节点的 id；同名的不同节点 id 不同。
- 同一台服务器从任一格式导入得到相同的 id。
- 单独占一个主机和端口的节点，机场轮换密码或 UUID 后 id 不变；更换服务器地址、端口、传输或 SNI 会得到新 id，客户端按“节点已不在订阅中”处理。
- id 只含 `[a-z0-9-]`，长度不超过约 80 个字符，满足引擎出站 id 规则（1–128 个 `[A-Za-z0-9._-]`），并给 iOS 联动组的 `s{序号}.` 前缀留了余量。

### 为什么凭据只在需要时参与

评审时有两种意见：把凭据指纹始终放进 id（区分同一服务器上的不同账号），或者完全不放（机场重置订阅 token 会轮换所有 UUID / 密码，id 跟着变就又丢了选择）。这里取中间：凭据只用来区分同一端点上真正不同的节点。这样常见的 token 重置不丢选择，同一端点上的不同账号也不会混成一个 id，并且绝大多数 id 不含任何由凭据导出的内容。

哈希算法、字段顺序和域分隔串（`anixops.node-id.endpoint.v1`、`anixops.node-id.credential.v1`）改动会改变所有 id，客户端保存的选择会全部失效；单元测试 `id_format_is_pinned` 固定了输出，改动前必须同时设计迁移。

## 旧 id 与迁移

每个订阅节点在元数据 `subscription.legacy_id`（`control_domain::NODE_METADATA_LEGACY_ID`）里带着按旧规则算出的 id；node-import 的 `ImportedNode.legacy_id` 把它交给客户端。

- `config_core::node_id::find_node(nodes, id)`：先按当前 id 找，找不到再按旧 id 找。
- `engine_embedded::nodes::single_node_envelope` 已改用它，返回的节点带新 id，调用方应保存新 id。

旧 id 本身依赖位置，所以**只有对生成旧 id 时的同一份订阅内容**按旧 id 查找才准确。客户端应在升级后第一次加载**本地已保存的订阅内容**时（刷新之前）把保存的旧 id 换成新 id 并写回；刷新后的新内容不要再用旧 id 查找，查不到就按“节点已不在订阅中”处理。旧 id 查找保留一个版本（1.0.x），之后移除。

客户端需要迁移的保存位置（详见 `docs/manual-intervention.md`）：

- 选中的节点 id；
- 策略组的选择（成员 id）和联动组默认值；
- 按节点 id 保存的节点编辑、延迟缓存等。
