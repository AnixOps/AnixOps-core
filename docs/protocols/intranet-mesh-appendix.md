## A. 区域间骨干消息

### A.1 通用约定

- 每条消息经骨干链路的可靠消息通道发送，格式为 `type(u8) ‖ 载荷`（规格 §17.3.7）。载荷除 LinkProbe 与 LinkProbeAck 外均为 pb 消息，编码规则同规格 §2.1。
- 单条消息（含 type 字节）不超过 **64 KiB**，也不超过链路报告的控制消息上限，取较小者。超出时发送方不发送并告警；接收方丢弃并计数。
- 未知 type：忽略并计数，不断开链路。已知 type 解码失败、字段越界或违反本节上限：丢弃该消息并计数，不断开链路，不转发。
- pb 中的未知字段一律跳过（向前兼容）。下表"必填"字段缺失视为解码失败。
- **骨干节点 ID** 为 u32，0 保留不用。
- **区域 ID** 即面板的地区代码，规则以 [mesh-status.md](../architecture/mesh-status.md)「节点程序管理 API」中 `PUT /v1/mesh` 的 `tag` 一条为准：2–16 位小写字母、数字或连字符，字母开头，不以连字符结尾。本区域网络在 `PUT /v1/mesh` 中的 `tag` 为 `mesh-<区域 ID>`。
- **序号 seq**：每个发布者对每类消息各维护一个 u64 计数。进程启动时取当前 Unix 毫秒时间；之后每次发布加 1；如果某次发布时当前 Unix 毫秒时间大于计数，就先把计数提到这个时间。这样重启后的序号总是大于重启前的序号，只要两次启动间的发布次数不超过经过的毫秒数。
- **新旧比较**：对同一 `(type, origin)`，seq 更大者为新。seq 相同、内容不同时，保留已有的一份并告警"序号重复"。

### A.2 RegionAdvert（type 1）

| 字段号 | 类型 | 名称 | 必填 | 上限与约束 |
| --- | --- | --- | --- | --- |
| 1 | uint32 | origin | 是 | 非 0，且在骨干成员清单中 |
| 2 | string | region | 是 | 区域 ID 规则；必须等于成员清单中 origin 所属的区域 |
| 3 | uint64 | seq | 是 | 非 0 |
| 4 | rep string | prefixes | 否 | 最多 1024 项；每项为规范 CIDR（主机位为 0），IPv4 前缀长度 8–32，IPv6 前缀长度 16–128；必须在规格 §15.4 的内网范围内 |
| 5 | bool | reachable | 否 | |
| 6 | uint32 | lifetime_s | 否 | 0 表示 90；取值 30–600，超出时按边界截断 |

接收规则（在规格 §17.3.3 基础上）：

1. origin 不在成员清单、region 与清单不符，或任一项前缀不合规：整条拒绝并计数，不转发。
2. 来自本区域 origin 的通告不改变本节点的选路（本区域内送达靠本区域网络），但照常保存和泛洪。
3. **其他区域** origin 的 prefixes 中与**本区域**汇总网段重叠的项：整条拒绝并告警"网段冲突"，不转发（规格 §17.3.3）。本区域 origin 的通告不做此项检查。不同区域之间的相同或重叠前缀按最长前缀匹配处理并告警，不拒绝。
4. 同一区域多个边界节点的 prefixes 不要求一致，目的区域按"通告了该前缀且 reachable"的边界节点集合计算候选出口。

### A.3 LinkState（type 2）

| 字段号 | 类型 | 名称 | 必填 | 上限与约束 |
| --- | --- | --- | --- | --- |
| 1 | uint32 | origin | 是 | 同 A.2 |
| 2 | uint64 | seq | 是 | 非 0 |
| 3 | rep LinkCost | links | 否 | 最多 256 项；neighbor 不重复 |
| 4 | uint32 | lifetime_s | 否 | 0 表示 60；取值 30–600 |

LinkCost：

| 字段号 | 类型 | 名称 | 必填 | 约束 |
| --- | --- | --- | --- | --- |
| 1 | uint32 | neighbor | 是 | 非 0，不等于 origin，且在成员清单中 |
| 2 | uint32 | cost_milli | 是 | 链路代价（规格 §17.3.4）乘以 1000 后四舍五入，上限 `0xFFFF_FFFE` |
| 3 | uint32 | loss_ppm | 否 | 0–1 000 000 |

- 只列出**可用**的链路（规格 §17.3.4：可用、已度量正常满 10 秒、且具备前向保密，见 A.6）。不可用的邻居不出现在列表中。
- 超过 lifetime_s 未刷新的 LinkState 作废，视为 origin 没有任何可用链路。
- 发布时机见规格 §17.3.4。

### A.4 LinkProbe / LinkProbeAck（type 3 / 4）

载荷不是 pb，而是定长 16 字节：`seq(u64 BE) ‖ sent_us(u64 BE)`。

- `seq`：发送方对该链路的探测序号，从 1 开始每次加 1。
- `sent_us`：发送方单调时钟的微秒值，只由发送方解释。
- 接收方收到 LinkProbe 后，立即以相同的 16 字节回 LinkProbeAck。长度不是 16 的探测丢弃。
- 发送方只接受 seq 在最近 30 个已发探测内、且尚未应答过的 Ack；其他 Ack 丢弃。超过 3 秒未应答的探测计为丢失。
- 每个方向各自探测，互不依赖。

### A.5 RelayUnreachable（type 5）

| 字段号 | 类型 | 名称 | 必填 | 约束 |
| --- | --- | --- | --- | --- |
| 1 | string | region | 是 | 区域 ID 规则 |

- 中转节点 T 无法把包送往目的区域时（见 A.7），向包的来源链路对端发送，同一 `(来源, 区域)` 每秒至多一条。
- 入口节点 I 收到后，把"经 T 中转到该区域"的路径标记为不可用，至少 10 秒，并在之后收到 T 新的 LinkState 时解除；随即对该区域的所有目的网段重新选路（不受规格 §17.3.5 的 60 秒间隔限制）。

### A.6 本附录对规格 §17.3 的细化

以下规则补充或取代规格 §17.3 的对应条文，实现以本节为准。

1. **前向保密是链路可用的前提**：骨干链路报告当前会话不具备前向保密时，该链路视为**不可用**：不发送也不接受 IP 包，不发送控制消息，代价为无穷大，也不列入 LinkState。同时上报告警 `backbone_link_insecure`（C.2），界面显示"骨干链路不满足安全要求"。告警在该链路恢复前向保密后撤销。（规格 §17.3.2 安全要求的执行方式。）
2. **度量逐字段取值**：rtt、loss、jitter、utilization 四项中，链路实现报告了的取链路值，没报告的由探测（A.4）补齐。同一字段只用一种来源，不混合计算：例如 rtt 取自链路时，探测得到的 rtt 只用于计算 jitter，不参与 rtt。来源按字段在链路每次上报时重新判断。四项中只要有一项需要探测，就对该链路每秒发一次 LinkProbe。utilization 没有来源时，代价公式中的拥塞系数取 1。
3. **禁止互连**（规格 §17.3.5 第 3 步）：被配置为禁止互连的区域对之间的骨干链路，不得出现在任何路径的任何一段上（直达 I → E，以及中转路径的 I → T 与 T → E 两段），也不在其上转发 IP 包。控制消息（区域通告、链路状态、探测）照常经这类链路收发，用于泛洪与度量。
4. **转发不携带出口 ID**：IP 包通道只承载原始 IP 包，因为骨干链路接口在接收端要按 IP 包头和网段检查每个包。转发规则见 A.7。
5. **跨区访问控制**：规格 §15.6 第 7 条的"源网段 → 目的网段"规则在**入口**边界节点上、在选路之前检查（配置见 B.4）。中转节点与出口节点不再检查访问控制，但出口节点仍按 A.7 检查目的。

### A.7 骨干转发（取代规格 §17.3.6 的旧格式）

入口节点 I：

1. 从本区域网络收到发给自己、目的 IP 不是本机地址的 Data 包（规格 §15.6 第 5 条）后，按最长前缀匹配在**其他区域**的汇总网段中查找目的；找不到时丢弃并计数 `no_route`。
2. 按 B.4 检查访问控制，不允许时丢弃并计数 `access`。
3. 取该目的网段当前选定的路径（规格 §17.3.5），把原始 IP 包发到路径第一段的链路：直达时发往出口 E，经中转时发往中转节点 T。经中转时，I 选定的 E 只用于计算代价，**实际出口由 T 决定**。
4. 链路的 `try_send` 失败时丢弃并计数 `link_send`，不改走其他链路；链路不可用会经度量触发重新选路。

收到骨干 IP 包的节点 N（来自链路对端 P，P 由收到包的链路确定）：

1. 目的 IP 落在**本区域**汇总网段内：N 是出口，按规格 §15.6 第 5 条送入本区域。N 与本区域网络不连通时丢弃并计数 `no_route`。
2. 否则 N 是中转节点。按最长前缀匹配，从区域通告的汇总网段中求出源 IP 所属区域 S 与目的 IP 所属区域 D。**只有当 P 的区域（取自成员清单）等于 S** 时，N 才继续转发；这表示该包在骨干上只走了一跳，P 就是入口。任一项求不出、或 P 的区域不等于 S 时，丢弃该包，计数 `inconsistent`，并告警 `backbone_forward_inconsistent`（每对 `(P, D)` 每分钟至多一次）。D 等于 S（P 把发往它自己区域的包交给了 N）时，丢弃并计数 `not_for_us`。
3. 继续转发时，N 在区域 D 的边界节点中，选一个 `reachable = true`、N 到它的链路可用、且 N 与它所在的区域对未被禁止互连（A.6 第 3 条）的节点，取链路代价最小者，代价相同取骨干 ID 较小者，直接发往该链路。**N 不再经第三个节点中转。**
4. 第 3 步找不到出口时丢弃，计数 `relay_unreachable`，并按 A.5 向 P 发 RelayUnreachable（区域 D）。

无环论证：只有从源区域 S 的节点收到的包才可能被继续转发（第 2 步）；这一判据只依赖包的源地址、收到包的链路和成员清单，不依赖任何节点的选路状态。入口 I 把包发往 E 或 T，T 可能与 I 同在 S 中。S 中的中转节点只直达它认为的目的区域 D 的出口，而 D 不等于 S（否则它会在第 1 步就地送达），所以下一跳一定在 S 以外；从 S 以外的节点收到的包不会再被转发。所以无论各节点的区域通告是否一致，一个包在骨干上最多经过 3 段链路，不会成环；各节点状态一致时最多 2 段（入口一段、中转一段）。

中转节点能看到明文 IP 包；骨干成员均由面板管理，互相信任（规格 §17.3.6）。

### A.8 IP 包通道的接收策略

边界节点按链路对端所在的区域，为每条骨干链路分别设置接收策略（链路接口的源、目的网段白名单），并在区域通告或成员清单变化时更新：

| 对端 | 源网段白名单 | 目的网段白名单 | 对应的走法 |
| --- | --- | --- | --- |
| 与本节点同区域 | 本区域的汇总网段 | 其他区域的汇总网段 | 同区域的入口把本节点当作中转（A.7，I 与 T 同在 S） |
| 在其他区域 | 除本区域以外所有区域的汇总网段 | 所有区域的汇总网段（含本区域，作为出口；含其他区域，作为中转） | 本节点作为出口或跨区中转 |

- "汇总网段"取本节点当前有效的区域通告（A.2）与本区域自己的汇总网段。
- 白名单为空（例如尚未收到任何其他区域的通告）时，链路拒绝所有 IP 包，与链路接口的默认拒绝一致。
- 速率上限取自 B.5。

### A.9 选路与防抖的细化

规格 §17.3.5 只规定了直达与中转之间的切换。实现按以下规则处理其余情况，阈值与规格相同：

1. **路径失效**：当前路径的任一段链路不可用、出口不再 `reachable` 或不再通告该网段、中转被 A.5 标记、或区域策略使其被删除时，立即按"初次选路"规则重选，不受 60 秒间隔限制。事件原因分别为 `down`、`relay_unreachable`、`policy`。
2. **直达换直达**（同一目的区域的另一个出口）：另一条直达健康，且代价 ≤ 当前代价 × 0.7 并至少低 20 ms，持续 5 秒后切换；当前直达 `loss` > 5% 而另一条直达健康时，持续 5 秒后切换（原因 `loss`）。
3. **当前直达 `loss` > 5%**：存在健康的其他直达时按第 2 条；否则在中转路径中选有效代价最小的一条，持续 5 秒后切换（原因 `loss`）。
4. **中转换中转**：另一条中转路径的有效代价 ≤ 当前有效代价 × 0.7 并至少低 20 ms，持续 5 秒后切换。
5. **持续时间**按条件计时：条件一直成立即可，期间最佳候选可以变化，到时切到当时的最佳候选；条件中断一次即重新计时。
6. **原因**：当前路径所在链路的 `utilization` 超过 0.8 且这是代价上升的主要来源时记为 `congestion`，否则代价条件记为 `latency`；从中转回到直达记为 `recovered`。
7. **中转节点不在目的区域**：按 A.7，目的区域的边界节点收到包就在本区域送达，经它"中转"等同于直达它本身。因此计算中转路径时不考虑目的区域内的节点（规格 §17.3.5 第 2 步）；中转节点可以在本区域或第三区域。
8. 每个目的网段的路径每秒最多重新计算一次；链路可用性变化、区域通告或链路状态变化时立即重新计算受影响的网段。

## B. 边界节点配置 `backbone` 节

`backbone` 是 `PUT /v1/mesh` 请求体中与 `networks` **同级的顶层对象**，每台边界节点一份；普通完整节点与接入端的请求体没有此节。它随请求体整体替换：省略或为 `null` 表示本节点不是边界节点，已运行的骨干全部停止。内核在 `GET /v1/status` 的 `features` 中列出 `mesh_backbone` 时才接受此节；未列出时 Agent 不下发（请求体拒绝未知字段）。详见 [mesh-status.md](../architecture/mesh-status.md)「节点程序管理 API」。

```json
{
  "networks": [ { "tag": "mesh-eu", "config_version": 1, "...": "..." } ],
  "backbone": {
    "id": 11,
    "region": "eu",
    "members": [
      { "id": 11, "region": "eu", "link": { "kind": "<链路实现名>", "params": {} } },
      { "id": 21, "region": "ap", "link": { "kind": "<链路实现名>", "params": {} } }
    ],
    "extra_prefixes": ["10.200.0.0/16"],
    "policy": {
      "deny_link": [["cn", "eu"], ["cn", "na"]],
      "preferred_transit": { "cn": ["ap"] }
    },
    "access": [
      { "from": ["10.10.0.0/16"], "to": ["10.20.0.0/16"] }
    ],
    "limits": { "ip_pps": 0, "ip_bps": 0 }
  }
}
```

### B.1 基本字段

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | u32 | 本节点骨干 ID，非 0，必须出现在 `members` 中 |
| `region` | string | 区域 ID 规则；必须等于 `members` 中本节点一项的区域；同一请求体的 `networks` 中必须有 `tag` 为 `mesh-<region>` 的网络，它就是本区域网络 |
| `members` | array | 2–256 项；`id` 不重复；每个区域至少一项。区域少于 2 个边界节点时只告警（规格 §15.6 要求每区域至少 2 个，属部署要求） |
| `members[].link` | object | `kind` 为已注册的骨干链路实现名，1–32 位小写字母、数字或连字符；`params` 原样交给实现，缺省为 `null`。到每个其他成员的链路用该成员一项的 `link` 打开（拨号还是接收由 `params` 决定），链路 ID 为 `backbone-<较小 ID>-<较大 ID>`，两端相同；本节点一项的 `link` 只检查 `kind`，不单独打开 |

`kind` 未注册（开源构建没有任何实现）时，`backbone` 不运行，状态给出 `failure.code = backbone_kind_unavailable`，本区域网络照常运行；这不算请求无效。链路实现拒绝某项 `params` 时同样不运行，`failure.code = backbone_link_refused`，`detail` 为字段路径加实现给出的固定原因。字段缺失、未知字段或违反上表约束时，整个请求体返回 400，不应用（与 `networks` 相同）。

**链路参数的保密**：`members[].link.params` 由链路实现解释，可能含密钥、证书或私钥。

- 其中的密钥部分与 `network.secret` 一样，由 Agent 从钥匙串（或节点的密钥存储）注入后下发，不写进面板保存的配置正文。
- `params` 不出现在任何应答、状态、事件、错误信息和日志中。错误信息只指出字段路径（例如 `backbone.members[3].link.params`）和违反的规则，不回显取值；链路实现返回的错误也按此处理后再上报。

### B.2 额外网段

`extra_prefixes`：面板配置的额外汇总网段（规格 §17.3.3 字段 4 第三类），最多 256 项，规则同 A.2 的 prefixes。

### B.3 区域策略

- `deny_link`：禁止互连的区域对列表，每项两个不同的区域 ID，无序，最多 256 项。见 A.6 第 3 条与规格 §17.3.5 第 3 步。
- `preferred_transit`：`源区域 → [中转区域]`。从源区域的入口出发、经列表中区域的中转路径，代价乘以 0.8（规格 §17.3.5 第 3 步）。
- 默认值（面板为四个默认区域生成）：`deny_link = [[cn, eu], [cn, na]]`，`preferred_transit = { cn: [ap] }`，即规格 §17.3.5 第 5 步。
- 两个字段中出现的区域 ID 不必已在 `members` 中（区域可以后加），但必须符合区域 ID 规则。

### B.4 跨区访问控制

- `access`：规则列表，最多 1024 项。每条规则 `from`、`to` 各为 1–64 个 CIDR。
- 入口节点对每个要发往骨干的包，检查是否存在一条规则，其 `from` 有一项包含源 IP、`to` 有一项包含目的 IP。存在则允许，否则拒绝。
- 规则有方向。回程包由对方区域的入口按其自己的规则检查，因此双向互通要两侧各配一条。
- 列表为空表示拒绝所有跨区流量（规格 §15.6 第 7 条默认拒绝）。

### B.5 速率

`limits.ip_pps`、`limits.ip_bps`：每条链路接收 IP 包的速率上限，0 表示链路实现的默认值。直接写入 A.8 的接收策略。

## C. 骨干的状态与事件

### C.1 状态

`GET /v1/mesh`（以及 `PUT /v1/mesh` 的应答）的顶层，与 `networks` 同级，增加 `backbone` 对象；本节点不是边界节点时为 `null`。字段名与 `GET /v1/mesh` 其余字段一样用下划线：

| 字段 | 内容 |
| --- | --- |
| `id`、`region` | 本节点骨干 ID 与区域 |
| `running`、`failure` | 骨干是否在运行；`failure` 为 `null` 或 `{ "code", "detail" }`，`code` 为 `backbone_kind_unavailable`、`backbone_link_refused` 或 `backbone_stopped`（运行中意外退出），`detail` 只含字段路径与固定原因 |
| `links[]` | 每个成员一项：`peer`、`region`、`up`、`forward_secrecy`、`transport`、`rtt_ms`、`loss_ppm`、`jitter_ms`、`cost`（无穷大时为 `null`）、`usable`（满足 A.6 第 1 条且已稳定 10 秒） |
| `regions[]` | 每个已知区域一项：`region`、`prefixes`、`borders[]`（`id`、`reachable`、`expires_in_s`） |
| `routes[]` | 每个其他区域的汇总网段一项：`prefix`、`region`、`egress`、`via`（经中转时为中转节点 ID，直达为 null）、`cost`、`since_s`（本路径选定至今的秒数） |
| `withdrawn` | bool：本节点当前是否因与骨干全部失联而撤回了汇总网段（规格 §15.6 第 6 条） |
| `counters` | 丢弃计数：`no_route`、`access`、`relay_unreachable`、`inconsistent`、`not_for_us`、`bad_message`、`unknown_type`、`link_send`，以及超出每秒 50 条而未列入 `events[]` 的事件数 `events_dropped` |
| `events[]` | 最近至多 64 条切换事件（C.2），旧的在前，每条另带 `seq`：从骨干启动时刻的 Unix 毫秒数起逐条加一，重启后仍递增，agent 按 `seq` 只上报新的 |
| `alerts[]` | 当前未撤销的告警 `{ "code", "peer", "detail" }`，`code` 见 C.2；不适用时 `peer` 为 0、`detail` 为空串 |

状态中不出现链路参数（`params`）、密钥或证书。Agent 把 `backbone` 原样随节点状态上报面板。

### C.2 切换事件

每次路径切换（规格 §17.3.5）产生一条事件，经 C.1 的 `events[]` 交给 agent：

| 字段 | 内容 |
| --- | --- |
| `kind` | `backbone_route_changed` |
| `prefix`、`region` | 目的网段与区域 |
| `from`、`to` | 旧路径与新路径，各为 `{egress, via}`；首次选路时 `from` 为 null |
| `reason` | `initial`、`latency`、`loss`、`congestion`、`down`、`recovered`、`relay_unreachable`、`policy` 之一 |

同一目的网段的事件按规格 §17.3.5 的切换间隔自然限速；所有事件合计每秒至多 50 条，超出只计数。

告警（进入 C.1 的 `alerts[]`，并作为事件上报一次）：

| `kind` | 触发 | 撤销 |
| --- | --- | --- |
| `backbone_link_insecure` | 某条链路报告当前会话不具备前向保密（A.6 第 1 条） | 该链路恢复前向保密 |
| `backbone_forward_inconsistent` | A.7 第 2 步丢弃 | 5 分钟内未再发生 |
| `backbone_prefix_conflict` | A.2 接收规则第 3 条，或不同区域通告重叠前缀 | 冲突的通告作废或改正 |
| `backbone_seq_duplicate` | A.1 序号相同、内容不同 | 5 分钟内未再发生 |
| `backbone_region_unreachable` | 某个其他区域的所有汇总网段都没有可用路径 | 该区域重新有可用路径 |

## D. 区域目录、区域探测、自动选区与迁区

本节给出规格 §15.8 第 7 条要求的消息格式，并按已实现的面板接口（anix-control `docs/design/mesh-regions/agent-contract.md` 第 4、5 节，下称"面板约定"）落实规格 §15.8 的流程。字段名：`PUT /v1/mesh`、`GET /v1/mesh` 与面板 HTTP 接口用下划线，快照用 lowerCamelCase（与 [mesh-status.md](../architecture/mesh-status.md) 一致）。

### D.1 角色与信任

| 步骤 | 谁处理 | 通道 |
| --- | --- | --- |
| 入网凭据 | 面板签发，`mse_` 开头的一次性令牌（面板约定第 4 节第 1 项）。只有 SHA-256 存在面板 | 安装命令或客户端带入 |
| 取目录（D.2） | 面板 | 设备：HTTPS，凭据或设备令牌作 Bearer；Agent 节点：随 `PUT /v1/mesh` 顶层 `region` 下发 |
| 测量（D.3、D.4） | 节点向各区域边界节点的探测应答器发探测包 | UDP，D.3 格式 |
| 首次选区与入区请求（D.5） | 面板：按节点报来的时延与偏好区域选区，分配地址，答复网络名、密钥与地址 | 设备：`POST /api/v5/mesh/device/enroll`；Agent 节点：mTLS 上报 |
| 重测与迁区建议（D.6） | 节点 | 结果经 `GET /v1/mesh` 交给 Agent，或随设备上报交给面板 |
| 迁区申请、撤回与结果（D.7） | 节点所有者发起，网络管理者在面板批准 | Agent：`mesh.region_request`；设备：`/api/v5/mesh/device/region-change` |
| 迁移执行（D.8） | 节点内核 | 面板下发的新配置 |

对规格 §15.8 第 1、2、4 条的落实：

1. 信任锚是面板的 TLS 身份，不是边界节点。规格原写"经目录入口取目录、由边界节点转交入区请求"，落实为节点直接向面板取目录和入区；面板不可直达的地区经区域控制面中继（需求 R33）访问面板，中继只转发 TLS，不终止。理由：
   - 边界节点因此**不持有任何面板写权限**，不参与准入。边界节点已是骨干信任汇聚点（规格 §15.6 第 7 条），不再给它增加"代面板核准"的权力。
   - 面板约定第 4 节的入网、地址分配、一次性凭据与重试窗口已实现并经审计，节点侧沿用，不另造第二条入网通道。
2. 入网凭据不再随附"目录入口"和面板签名：目录经 TLS 从面板取得，凭据只是令牌。目录同样不含任何网络名、网络密钥或地址。
3. 边界节点只做一件事：应答探测（D.3）。探测应答器的静态公钥随目录下发，节点据此认证应答，防止路径上的第三方伪造"更快"的应答。

### D.2 区域目录

#### D.2.1 设备取目录

```
GET /api/v5/mesh/device/directory
Authorization: Bearer <mse_ 入网凭据 | msd_ 设备令牌>
→ 200 {"data": <目录>}
```

- 用入网凭据取目录**不消耗**凭据。凭据未知、已使用（超过面板约定的 10 分钟重试窗口）、已过期或已撤销，或设备令牌无效时回 401。按来源地址限流，与面板约定第 4 节其他接口相同。
- 功能 `mesh` 关闭时回 404 `feature_disabled`。

#### D.2.2 目录对象

```json
{
  "version": 1,
  "preferred": "ap",
  "regions": [
    {
      "code": "eu",
      "subnet": "10.130.0.0/16",
      "borders": [
        { "name": "fra-border-1", "probe": "198.51.100.7:11013", "key": "B6N8vBQgk8i3VdwbEOhstCY3StFqqFPtC9/AsrhtHHw=" }
      ]
    }
  ]
}
```

| 字段 | 约束 |
| --- | --- |
| `version` | 固定 1。其他值整个目录拒绝 |
| `preferred` | 偏好区域代码或 `null`。只用于界面展示；首次选区的偏好系数由面板计算（D.5），节点不得在上报的时延中自行乘系数 |
| `regions` | 0–64 项（为空时节点不测量），`code` 不重复，符合区域 ID 规则（A.1）。只列已启用、且至少一台边界节点已有探测公钥的区域 |
| `regions[].subnet` | 区域虚拟子网，IPv4 CIDR，主机位为 0。各区域互不重叠（规格 §15.6 第 1 条），重叠时整个目录拒绝 |
| `regions[].borders` | 1–16 项 |
| `borders[].name` | 边界节点的显示名，1–63 字节的小写字母、数字或连字符，不以连字符开头或结尾；同一区域内不重复。只用于界面（快照 `self.regionBasis.border`） |
| `borders[].probe` | 探测地址：IPv4 字面量 `a.b.c.d:port` 或 IPv6 字面量 `[addr]:port`，端口 1–65535。**不接受主机名**（不为探测做 DNS 解析）。地址须为单播地址；回环、链路本地、组播、广播、未指定地址拒绝该项（目录只来自面板，见 D.11；私有地址允许，供同一内网中的部署与实验室使用） |
| `borders[].key` | 该边界节点探测应答器的 X25519 公钥，标准 base64（带填充，44 字符）。全零或已知的低阶点拒绝该项 |

- 未知字段一律拒绝（与面板约定第 4 节第 3 项一致：设备只接受固定字段）。
- 某一项 `borders[]` 不合规时只丢弃该项；某区域因此没有边界节点时该区域不参与测量，并在 `region_probe.rejected` 中计数。顶层字段不合规时整个目录拒绝，保留上一份可用目录。
- 目录不超过 64 KiB。

#### D.2.3 Agent 节点

Agent 节点不取目录：面板在下发给 Agent 的配置中带上目录，Agent 放进 `PUT /v1/mesh` 的顶层 `region` 对象（D.9.1）。

### D.3 探测包

UDP，无连接。所有多字节整数为大端。

**请求**（节点 → 探测应答器），长度**恰为 128 字节**：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 魔数 `A7 1C 5E 02` |
| 4 | 1 | 版本 `01` |
| 5 | 1 | 类型 `01`（请求） |
| 6 | 2 | 保留，填 0 |
| 8 | 32 | 节点本轮的临时 X25519 公钥 `E` |
| 40 | 16 | 随机数 `nonce`（每个探测包新取） |
| 56 | 4 | 序号 `seq`（本轮内从 0 起） |
| 60 | 68 | 填充，全 0 |

**应答**（探测应答器 → 节点），长度**恰为 44 字节**：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 魔数 `A7 1C 5E 02` |
| 4 | 1 | 版本 `01` |
| 5 | 1 | 类型 `02`（应答） |
| 6 | 2 | 保留，填 0 |
| 8 | 16 | 原样回送的 `nonce` |
| 24 | 4 | 原样回送的 `seq` |
| 28 | 16 | `tag` |

计算：

```
shared = X25519(S_priv, E)            // 应答器；节点侧为 X25519(e_priv, S)
        全零（低阶点）时丢弃请求，不应答
K      = HKDF-SHA256(salt = "mesh-region-probe/v1", ikm = shared, info = S ‖ E, L = 32)
tag    = HMAC-SHA256(K, 应答[0..28])[0..16]
```

`S` 为应答器公钥（目录中的 `key`）。盐是 ASCII 字节串，不含结尾 0。

规则：

- **防放大**：应答（44 字节）小于请求（128 字节），且应答器对每个请求至多回一个应答。长度不是 128、魔数、版本、类型或保留字段不对的请求直接丢弃，不应答，只计数。填充非 0 同样丢弃。
- **应答器限速**：每个来源地址（IPv4 按 /32，IPv6 按 /64）令牌桶每秒 50 个、突发 20 个；全局每秒 5000 个。超出直接丢弃并计数。应答器可以缓存最近 1024 个 `E` 对应的 `K`，避免重复做 X25519。
- **节点校验**：应答的来源地址和端口必须等于该探测包的目标；`nonce` 与 `seq` 必须对应一个已发出、未应答、未超时的探测；`tag` 用常量时间比较。任一不符就丢弃，不算丢包也不算应答。
- **临时密钥**：每轮对每台边界节点新生成一个临时密钥对，本轮结束即擦除，不落盘。
- 应答器公钥由边界节点自行生成并保存（D.9.3），私钥不离开节点。

### D.4 一轮测量

1. 对目录中每个区域的每台边界节点各发 **10 个**探测包，间隔 100 毫秒；不同边界节点并行，同时至多 16 台。
2. 每个探测包最多等 **1000 毫秒**，超时算丢失。RTT 用单调时钟，取毫秒（小数）。
3. **边界节点中位 RTT**：至少收到 5 个有效应答才有效，取有效应答 RTT 的中位数（个数为偶数时取中间两个的平均）；否则该边界节点本轮无效。
4. **区域中位 RTT**：该区域各有效边界节点中位 RTT 的**最小值**（成员按最近的边界节点出区，规格 §15.6 第 6 条）。没有有效边界节点时，该区域本轮不可达，不出现在结果中。
5. 上报和比较时 RTT 四舍五入到 0.1 毫秒。
6. 一轮所有区域都不可达时，本轮结果为空，不用于首次选区，也不计入 D.6 的连续判定（见 D.6 第 3 条）。

### D.5 首次入网自动选区（面板）

1. 设备：入网请求的 `latencies` 即 D.4 的区域中位 RTT（面板约定第 4 节第 2 项）。设备在入网前完成一轮测量；`network.joining.stage` 为 `measuring_regions`。
2. Agent 节点：面板未给节点指定区域时，按节点上报的 `region_probe.regions`（D.9.2）选区。
3. 面板计算每个已启用区域的得分：`score = rtt × 0.8`（该区域为偏好区域）或 `score = rtt`（其他区域），取得分最小者。得分相同时按面板区域列表的顺序（`sort` 升序，再按 ID 升序）。没有任何已启用区域有时延时拒绝（面板约定第 4 节第 2 项）。
4. 偏好区域：签发入网凭据时可指定 `preferred_region`（地区代码）；未指定时取面板组网设置中的默认偏好区域；都没有时不打折。凭据已指定区域时直接用该区域，不看时延。
5. 面板分配地址后才答复网络配置（规格 §15.10.2 第 5 条）；节点在拿到配置前不加入任何区域网络。

### D.6 重测与迁区建议（节点）

1. 节点加入区域网络后，在 1–5 分钟内（均匀随机）做第一轮测量，之后每 **6 小时**一轮，每轮另加 0–10 分钟的均匀随机延迟。目录变化后的下一轮按新目录。
2. 每轮记录 `{at（Unix 秒）, 各区域 RTT}`。节点在状态目录保存最近 8 轮（文件 `region-probe.json`，权限 0600），重启后读回；文件损坏时丢弃，从头积累。
3. 对当前区域 X 与另一区域 Y，**一轮满足**当且仅当本轮 X 与 Y 都可达，且 `rtt(Y) ≤ 0.7 × rtt(X)` 并且 `rtt(X) − rtt(Y) ≥ 30`。
4. 对 Y 的**连续满足段**：按时间倒序从最近一轮往前数，每轮都对 Y 满足，且相邻两轮间隔不超过 **7 小时**（6 小时加随机延迟与余量）。任何一轮不满足、X 不可达、结果为空，或间隔超过 7 小时（节点离线），都使连续段在此中断。
5. 连续满足段的最早一轮与最近一轮相差 **≥ 24 小时**（即至少 5 轮）时，发出迁区建议：建议区域 Y、当前区域与 Y 最近一轮的中位 RTT、条件开始成立的时间（连续段最早一轮）。该网络已有 `pending` 申请时不给出建议。多个区域同时满足时取最近一轮 RTT 最小者，再按区域代码字典序。
6. 最近一轮对建议的区域不再满足时，建议立即撤销。节点区域变化（迁移完成）后清空已保存的各轮记录，从头积累。
7. 建议只用于提示（规格 §15.8 第 5 条）：节点不自动发出迁区申请，也不自动迁移。
8. 节点没有目录时不测量，`region_probe` 为 `null`。

### D.7 迁区申请、撤回与结果

字段与命令以 [mesh-status.md](../architecture/mesh-status.md) 与 [mesh-module.md](../architecture/mesh-module.md) 为准（能力 `mesh_region_request_state`），本节只给出流程：

1. **申请**：节点所有者经命令 `mesh_request_region` 发起。Agent 节点经 `mesh.region_request` 送到面板（面板约定第 5 节）；设备经 `POST /api/v5/mesh/device/region-change`（面板约定第 4 节第 3 项）。网络管理者也可以在面板直接发起迁移。
2. **撤回**：命令 `mesh_withdraw_region_request { network }` 在 `region_requests` 中记一条 `withdraw: true` 的记录。Agent 把它作为 `mesh.region_request` 载荷 `{"withdraw": true}` 送出；设备调用 `DELETE /api/v5/mesh/device/region-change`。面板删除该节点待审批的申请（没有时也回成功），之后 Agent 或设备删除这一条记录。
3. **结果回送**：面板在该网络的配置中下发 `region_request`（`null` 或 `{ "id", "region", "state", "reason", "reject_reason" }`，`state` 为 `pending` 或 `rejected`）。Agent 节点经 Agent 下发；设备在 `GET /api/v5/mesh/device/config` 应答的该网络中取得（面板约定第 4 节第 3 项的固定字段增加 `region_request`）。被拒的申请保留到节点再次申请或撤回为止；批准后不再下发，新区域的网络随配置下发（D.8）。

### D.8 迁移执行（节点）

批准后面板为节点分配新区域的地址、清空节点在旧区域登记的静态公钥（面板约定第 4 节第 3 项），并在下一次配置中以新区域网络（`tag` 为 `mesh-<新区域>`）取代旧区域网络。内核按规格 §15.8 第 6 条执行：

1. 同一次 `PUT /v1/mesh` 中，旧区域网络被移除、新区域网络被加入。新区域的网络名、密钥和地址此时已在请求体中，即"先取得"。
2. 内核先停止被移除的网络：按规格 §15.7 第 6 条撤回本节点在旧区域通告的全部子网与组地址段，路由信息 version 加 1 并立即同步，等待 3 秒后断开。期间快照的 `self.regionState` 为 `migrating`。
3. 旧网络停止后再启动新区域网络（端口与虚拟网卡名先释放）。新网络的静态密钥按新的 `network.name` 生成（规格 §8.1），由迁移后的首次上报登记到面板；新区域的 `native_keys` 收录它之前，新网络处于 `native_keys_pending`（规格 §8.3.1），这是迁移期间的正常状态。
4. 宿主组网关迁移时，组地址段随网关进入新区域网络配置，地址段本身不变（规格 §15.8 第 6 条）。
5. 迁移完成后清空 D.6 的测量记录与迁区建议。

### D.9 节点程序管理 API 与快照

#### D.9.1 `PUT /v1/mesh` 顶层 `region`

与 `networks` 同级，可省略或为 `null`（不测量，区域来由未知）：

```json
{
  "region": {
    "current": "eu",
    "basis": "latency",
    "directory": { "version": 1, "preferred": null, "regions": [ ] }
  }
}
```

| 字段 | 约束 |
| --- | --- |
| `current` | 节点当前所在区域代码，或 `null`（未分配）。不为 `null` 时请求体中必须有 `tag` 为 `mesh-<current>` 的网络 |
| `basis` | 当前区域的来由：`latency`（首次按时延自动选区）、`credential`（签发凭据时指定）、`admin`（管理员指定或直接发起迁移）、`migration`（节点申请经批准迁入）；`current` 为 `null` 时为 `null` |
| `directory` | D.2.2 的目录对象，或 `null`；可省略，视为 `null` |

未知字段或违反约束时整个请求体返回 400，与 `networks` 相同。设备从 `GET /api/v5/mesh/device/config` 应答的顶层 `region`（同一形态，面板约定第 4 节第 3 项新增的顶层字段）取得同样内容，转成这一节。

边界节点也带 `region`（`current` 为其本区域）；边界节点不计算迁区建议。

#### D.9.2 `GET /v1/mesh` 顶层 `region_probe`

`null`（没有目录）或：

```json
{
  "measured_at": "2026-11-26T03:00:00Z",
  "next_at": "2026-11-26T09:04:12Z",
  "regions": [ { "region": "eu", "rtt_ms": 18.4 }, { "region": "ap", "rtt_ms": 211.0 } ],
  "unreachable": ["na"],
  "rejected": 0,
  "suggestion": null
}
```

- `measured_at` 为最近一轮完成时间（尚未完成任何一轮时为 `null`），`next_at` 为下一轮计划时间。
- `regions` 只含本轮可达的区域，按区域代码排序；`unreachable` 为本轮不可达的区域代码。
- `rejected` 为目录中因不合规被丢弃的边界节点数（D.2.2）。
- `suggestion`：`null` 或 `{ "region", "current_median_ms", "suggested_median_ms", "since" }`（D.6 第 5 条；两项 RTT 为整数毫秒，四舍五入；`since` 为 RFC 3339 UTC）。已有 `pending` 申请时为 `null`。

Agent 把 `region_probe` 原样随 `mesh.status` 上报；设备在 `POST /api/v5/mesh/device/report` 的载荷顶层带上同一对象。面板用 `regions` 为未分配区域的 Agent 节点选区（D.5 第 2 条），并在节点详情中显示 `suggestion`。

#### D.9.3 边界节点 `backbone.probe`

`PUT /v1/mesh` 的 `backbone`（B 节）增加可选的 `probe`：

```json
{ "probe": { "listen": ["0.0.0.0:11013", "[::]:11013"] } }
```

- `listen`：1–4 个 UDP 套接字地址（IP 字面量加端口）。省略 `probe` 或为 `null` 时不开应答器。
- 应答器公钥：内核首次需要时生成 X25519 密钥对，私钥保存在状态目录 `keys/region-probe`（0600），重启后不变；只有删除状态目录才会更换。私钥不出现在任何应答、状态、事件和日志中。
- `GET /v1/mesh` 的 `backbone` 状态增加 `probe`：`null` 或 `{ "public_key", "listening": [地址], "failure", "counters": { "answered", "malformed", "rate_limited", "low_order" } }`。`failure` 为 `null` 或 `{ "code": "region_probe_bind_failed", "detail" }`。Agent 原样上报（`backbone` 本来就原样上报）；面板取 `public_key` 和该节点的公网地址与端口生成目录。

#### D.9.4 快照

`self.regionRequest`、`self.regionSuggestion` 见 mesh-status.md。`self` 的其他 0.4 区域字段：

| 字段 | 取值 |
| --- | --- |
| `self.region` | 当前区域代码，或 `null` |
| `self.regionBasis` | `null`，或对象 `{ "kind", "border", "latencyMs" }`：`kind` 为 D.9.1 的 `basis`；`kind = latency` 且有测量结果时，`border` 为当前区域中位 RTT 最小的边界节点显示名（D.2.2 `name`），`latencyMs` 为其中位 RTT（整数毫秒）；否则两项为 `null`。客户端遇到不认识的 `kind` 按 `other` 处理，仍可显示 `border` 与 `latencyMs` |
| `self.regionState` | `auto`（按时延自动选区）、`pinned`（凭据、管理员指定或经批准迁入）、`pending`（有待审批的迁区申请，优先于前两者）、`migrating`（D.8 第 2 步，优先于以上各项）、`measuring`（入网前测量中）、`unassigned`（未分配区域） |

顶层 `regionProbe`：与 D.9.2 相同的内容，字段名改为 lowerCamelCase。

#### D.9.5 能力与命令

- 能力 `mesh_region_probe`（内核 0.4）：接受 D.9.1 的 `region` 与 D.9.3 的 `backbone.probe`，给出 D.9.2、`regionProbe`、`self.regionBasis`、`self.regionSuggestion`。内核未列出时 Agent 与面板不下发 `region` 与 `backbone.probe`。
- 迁区申请状态与撤回属于能力 `mesh_region_request_state`（mesh-status.md），与本能力独立。

### D.10 入网凭据只用一次（节点侧）

- 节点在入网成功（取得设备令牌）后立即从内存和磁盘删除入网凭据；之后只用设备令牌。
- 入网应答丢失时，节点在面板约定的 10 分钟重试窗口内用同一凭据与同一 `device_key` 重试；超过窗口或收到 401 时删除凭据并报 `credential_invalid`，不再重试。
- 凭据、设备令牌、网络密钥不出现在任何状态、事件、错误信息和日志中（错误只给字段名与规则）。

### D.11 安全说明

- 路径上的第三方无法伪造更快的应答（D.3 的 `tag` 以应答器私钥认证），只能延迟或丢弃，使某区域显得更慢；这最多导致选到次优区域，且迁移必须经网络管理者批准（规格 §15.8 第 5 条）。
- 目录只经 TLS 从面板取得（或经 mTLS 的 Agent 通道），节点不接受其他来源的目录。
- 应答器不持有任何网络密钥，不参与准入；被攻破的应答器只能谎报时延。
- 取目录需要有效的凭据或设备令牌，避免边界节点公网地址被任意枚举；凭据持有者本来就会入网并连接边界节点。
