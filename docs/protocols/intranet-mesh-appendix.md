## A. 区域间骨干消息

### A.1 通用约定

- 每条消息经骨干链路的可靠消息通道发送，格式为 `type(u8) ‖ 载荷`（规格 §17.3.7）。载荷除 LinkProbe 与 LinkProbeAck 外均为 pb 消息，编码规则同规格 §2.1。
- 单条消息（含 type 字节）不超过 **64 KiB**，也不超过链路报告的控制消息上限，取较小者。超出时发送方不发送并告警；接收方丢弃并计数。
- 未知 type：忽略并计数，不断开链路。已知 type 解码失败、字段越界或违反本节上限：丢弃该消息并计数，不断开链路，不转发。
- pb 中的未知字段一律跳过（向前兼容）。下表"必填"字段缺失视为解码失败。
- **骨干节点 ID** 为 u32，0 保留不用。
- **区域 ID** 即面板的地区代码，规则以 [mesh-status.md](../architecture/mesh-status.md)「节点程序管理 API」中 `PUT /v1/mesh` 的 `tag` 一条为准：2–16 位小写字母、数字或连字符，字母开头，不以连字符结尾。本区域网络在 `PUT /v1/mesh` 中的 `tag` 为 `mesh-<区域 ID>`。
- **序号 seq**：每个发布者对每类消息各维护一个 u64 计数。进程启动时取当前 Unix 毫秒时间；之后每次发布加 1；如果某次发布时当前 Unix 毫秒时间大于计数，就先把计数提到这个时间。这样重启后的序号总是大于重启前的序号，只要两次启动间的发布次数不超过经过的毫秒数。
- **新旧比较**：对同一 `(type, origin)`，seq 更大者为新。seq 相同、内容不同时，保留已有的一份并告警"序号重复"。

### A.2 RegionAdvert（type 1）

| 字段号 | 类型 | 名称 | 必填 | 上限与约束 |
| --- | --- | --- | --- | --- |
| 1 | uint32 | origin | 是 | 非 0，且在骨干成员清单中 |
| 2 | string | region | 是 | 区域 ID 规则；必须等于成员清单中 origin 所属的区域 |
| 3 | uint64 | seq | 是 | 非 0 |
| 4 | rep string | prefixes | 否 | 最多 1024 项；每项为规范 CIDR（主机位为 0），IPv4 前缀长度 8–32，IPv6 前缀长度 16–128；必须在规格 §15.4 的内网范围内 |
| 5 | bool | reachable | 否 | |
| 6 | uint32 | lifetime_s | 否 | 0 表示 90；取值 30–600，超出时按边界截断 |

接收规则（在规格 §17.3.3 基础上）：

1. origin 不在成员清单、region 与清单不符，或任一项前缀不合规：整条拒绝并计数，不转发。
2. 来自本区域 origin 的通告不改变本节点的选路（本区域内送达靠本区域网络），但照常保存和泛洪。
3. **其他区域** origin 的 prefixes 中与**本区域**汇总网段重叠的项：整条拒绝并告警"网段冲突"，不转发（规格 §17.3.3）。本区域 origin 的通告不做此项检查。不同区域之间的相同或重叠前缀按最长前缀匹配处理并告警，不拒绝。
4. 同一区域多个边界节点的 prefixes 不要求一致，目的区域按"通告了该前缀且 reachable"的边界节点集合计算候选出口。

### A.3 LinkState（type 2）

| 字段号 | 类型 | 名称 | 必填 | 上限与约束 |
| --- | --- | --- | --- | --- |
| 1 | uint32 | origin | 是 | 同 A.2 |
| 2 | uint64 | seq | 是 | 非 0 |
| 3 | rep LinkCost | links | 否 | 最多 256 项；neighbor 不重复 |
| 4 | uint32 | lifetime_s | 否 | 0 表示 60；取值 30–600 |

LinkCost：

| 字段号 | 类型 | 名称 | 必填 | 约束 |
| --- | --- | --- | --- | --- |
| 1 | uint32 | neighbor | 是 | 非 0，不等于 origin，且在成员清单中 |
| 2 | uint32 | cost_milli | 是 | 链路代价（规格 §17.3.4）乘以 1000 后四舍五入，上限 `0xFFFF_FFFE` |
| 3 | uint32 | loss_ppm | 否 | 0–1 000 000 |

- 只列出**可用**的链路（规格 §17.3.4：可用、已度量正常满 10 秒、且具备前向保密，见 A.6）。不可用的邻居不出现在列表中。
- 超过 lifetime_s 未刷新的 LinkState 作废，视为 origin 没有任何可用链路。
- 发布时机见规格 §17.3.4。

### A.4 LinkProbe / LinkProbeAck（type 3 / 4）

载荷不是 pb，而是定长 16 字节：`seq(u64 BE) ‖ sent_us(u64 BE)`。

- `seq`：发送方对该链路的探测序号，从 1 开始每次加 1。
- `sent_us`：发送方单调时钟的微秒值，只由发送方解释。
- 接收方收到 LinkProbe 后，立即以相同的 16 字节回 LinkProbeAck。长度不是 16 的探测丢弃。
- 发送方只接受 seq 在最近 30 个已发探测内、且尚未应答过的 Ack；其他 Ack 丢弃。超过 3 秒未应答的探测计为丢失。
- 每个方向各自探测，互不依赖。

### A.5 RelayUnreachable（type 5）

| 字段号 | 类型 | 名称 | 必填 | 约束 |
| --- | --- | --- | --- | --- |
| 1 | string | region | 是 | 区域 ID 规则 |

- 中转节点 T 无法把包送往目的区域时（见 A.7），向包的来源链路对端发送，同一 `(来源, 区域)` 每秒至多一条。
- 入口节点 I 收到后，把"经 T 中转到该区域"的路径标记为不可用，至少 10 秒，并在之后收到 T 新的 LinkState 时解除；随即对该区域的所有目的网段重新选路（不受规格 §17.3.5 的 60 秒间隔限制）。

### A.6 本附录对规格 §17.3 的细化

以下规则补充或取代规格 §17.3 的对应条文，实现以本节为准。

1. **前向保密是链路可用的前提**：骨干链路报告当前会话不具备前向保密时，该链路视为**不可用**：不发送也不接受 IP 包，不发送控制消息，代价为无穷大，也不列入 LinkState。同时上报告警 `backbone_link_insecure`（C.2），界面显示"骨干链路不满足安全要求"。告警在该链路恢复前向保密后撤销。（规格 §17.3.2 安全要求的执行方式。）
2. **度量逐字段取值**：rtt、loss、jitter、utilization 四项中，链路实现报告了的取链路值，没报告的由探测（A.4）补齐。同一字段只用一种来源，不混合计算：例如 rtt 取自链路时，探测得到的 rtt 只用于计算 jitter，不参与 rtt。来源按字段在链路每次上报时重新判断。四项中只要有一项需要探测，就对该链路每秒发一次 LinkProbe。utilization 没有来源时，代价公式中的拥塞系数取 1。
3. **禁止互连**（规格 §17.3.5 第 3 步）：被配置为禁止互连的区域对之间的骨干链路，不得出现在任何路径的任何一段上（直达 I → E，以及中转路径的 I → T 与 T → E 两段），也不在其上转发 IP 包。控制消息（区域通告、链路状态、探测）照常经这类链路收发，用于泛洪与度量。
4. **转发不携带出口 ID**：IP 包通道只承载原始 IP 包，因为骨干链路接口在接收端要按 IP 包头和网段检查每个包。转发规则见 A.7。
5. **跨区访问控制**：规格 §15.6 第 7 条的"源网段 → 目的网段"规则在**入口**边界节点上、在选路之前检查（配置见 B.4）。中转节点与出口节点不再检查访问控制，但出口节点仍按 A.7 检查目的。

### A.7 骨干转发（取代规格 §17.3.6 的旧格式）

入口节点 I：

1. 从本区域网络收到发给自己、目的 IP 不是本机地址的 Data 包（规格 §15.6 第 5 条）后，按最长前缀匹配在**其他区域**的汇总网段中查找目的；找不到时丢弃并计数 `no_route`。
2. 按 B.4 检查访问控制，不允许时丢弃并计数 `access`。
3. 取该目的网段当前选定的路径（规格 §17.3.5），把原始 IP 包发到路径第一段的链路：直达时发往出口 E，经中转时发往中转节点 T。经中转时，I 选定的 E 只用于计算代价，**实际出口由 T 决定**。
4. 链路的 `try_send` 失败时丢弃并计数 `link_send`，不改走其他链路；链路不可用会经度量触发重新选路。

收到骨干 IP 包的节点 N（来自链路对端 P，P 由收到包的链路确定）：

1. 目的 IP 落在**本区域**汇总网段内：N 是出口，按规格 §15.6 第 5 条送入本区域。N 与本区域网络不连通时丢弃并计数 `no_route`。
2. 否则 N 是中转节点。按最长前缀匹配，从区域通告的汇总网段中求出源 IP 所属区域 S 与目的 IP 所属区域 D。**只有当 P 的区域（取自成员清单）等于 S** 时，N 才继续转发；这表示该包在骨干上只走了一跳，P 就是入口。任一项求不出、或 P 的区域不等于 S 时，丢弃该包，计数 `inconsistent`，并告警 `backbone_forward_inconsistent`（每对 `(P, D)` 每分钟至多一次）。D 等于 S（P 把发往它自己区域的包交给了 N）时，丢弃并计数 `not_for_us`。
3. 继续转发时，N 在区域 D 的边界节点中，选一个 `reachable = true`、N 到它的链路可用、且 N 与它所在的区域对未被禁止互连（A.6 第 3 条）的节点，取链路代价最小者，代价相同取骨干 ID 较小者，直接发往该链路。**N 不再经第三个节点中转。**
4. 第 3 步找不到出口时丢弃，计数 `relay_unreachable`，并按 A.5 向 P 发 RelayUnreachable（区域 D）。

无环论证：只有从源区域 S 的节点收到的包才可能被继续转发（第 2 步）；这一判据只依赖包的源地址、收到包的链路和成员清单，不依赖任何节点的选路状态。入口 I 把包发往 E 或 T，T 可能与 I 同在 S 中。S 中的中转节点只直达它认为的目的区域 D 的出口，而 D 不等于 S（否则它会在第 1 步就地送达），所以下一跳一定在 S 以外；从 S 以外的节点收到的包不会再被转发。所以无论各节点的区域通告是否一致，一个包在骨干上最多经过 3 段链路，不会成环；各节点状态一致时最多 2 段（入口一段、中转一段）。

中转节点能看到明文 IP 包；骨干成员均由面板管理，互相信任（规格 §17.3.6）。

### A.8 IP 包通道的接收策略

边界节点按链路对端所在的区域，为每条骨干链路分别设置接收策略（链路接口的源、目的网段白名单），并在区域通告或成员清单变化时更新：

| 对端 | 源网段白名单 | 目的网段白名单 | 对应的走法 |
| --- | --- | --- | --- |
| 与本节点同区域 | 本区域的汇总网段 | 其他区域的汇总网段 | 同区域的入口把本节点当作中转（A.7，I 与 T 同在 S） |
| 在其他区域 | 除本区域以外所有区域的汇总网段 | 所有区域的汇总网段（含本区域，作为出口；含其他区域，作为中转） | 本节点作为出口或跨区中转 |

- "汇总网段"取本节点当前有效的区域通告（A.2）与本区域自己的汇总网段。
- 白名单为空（例如尚未收到任何其他区域的通告）时，链路拒绝所有 IP 包，与链路接口的默认拒绝一致。
- 速率上限取自 B.5。

### A.9 选路与防抖的细化

规格 §17.3.5 只规定了直达与中转之间的切换。实现按以下规则处理其余情况，阈值与规格相同：

1. **路径失效**：当前路径的任一段链路不可用、出口不再 `reachable` 或不再通告该网段、中转被 A.5 标记、或区域策略使其被删除时，立即按"初次选路"规则重选，不受 60 秒间隔限制。事件原因分别为 `down`、`relay_unreachable`、`policy`。
2. **直达换直达**（同一目的区域的另一个出口）：另一条直达健康，且代价 ≤ 当前代价 × 0.7 并至少低 20 ms，持续 5 秒后切换；当前直达 `loss` > 5% 而另一条直达健康时，持续 5 秒后切换（原因 `loss`）。
3. **当前直达 `loss` > 5%**：存在健康的其他直达时按第 2 条；否则在中转路径中选有效代价最小的一条，持续 5 秒后切换（原因 `loss`）。
4. **中转换中转**：另一条中转路径的有效代价 ≤ 当前有效代价 × 0.7 并至少低 20 ms，持续 5 秒后切换。
5. **持续时间**按条件计时：条件一直成立即可，期间最佳候选可以变化，到时切到当时的最佳候选；条件中断一次即重新计时。
6. **原因**：当前路径所在链路的 `utilization` 超过 0.8 且这是代价上升的主要来源时记为 `congestion`，否则代价条件记为 `latency`；从中转回到直达记为 `recovered`。
7. **中转节点不在目的区域**：按 A.7，目的区域的边界节点收到包就在本区域送达，经它"中转"等同于直达它本身。因此计算中转路径时不考虑目的区域内的节点（规格 §17.3.5 第 2 步）；中转节点可以在本区域或第三区域。
8. 每个目的网段的路径每秒最多重新计算一次；链路可用性变化、区域通告或链路状态变化时立即重新计算受影响的网段。

## B. 边界节点配置 `backbone` 节

`backbone` 是 `PUT /v1/mesh` 请求体中与 `networks` **同级的顶层对象**，每台边界节点一份；普通完整节点与接入端的请求体没有此节。它随请求体整体替换：省略或为 `null` 表示本节点不是边界节点，已运行的骨干全部停止。内核在 `GET /v1/status` 的 `features` 中列出 `mesh_backbone` 时才接受此节；未列出时 Agent 不下发（请求体拒绝未知字段）。详见 [mesh-status.md](../architecture/mesh-status.md)「节点程序管理 API」。

```json
{
  "networks": [ { "tag": "mesh-eu", "config_version": 1, "...": "..." } ],
  "backbone": {
    "id": 11,
    "region": "eu",
    "members": [
      { "id": 11, "region": "eu", "link": { "kind": "<链路实现名>", "params": {} } },
      { "id": 21, "region": "ap", "link": { "kind": "<链路实现名>", "params": {} } }
    ],
    "extra_prefixes": ["10.200.0.0/16"],
    "policy": {
      "deny_link": [["cn", "eu"], ["cn", "na"]],
      "preferred_transit": { "cn": ["ap"] }
    },
    "access": [
      { "from": ["10.10.0.0/16"], "to": ["10.20.0.0/16"] }
    ],
    "limits": { "ip_pps": 0, "ip_bps": 0 }
  }
}
```

### B.1 基本字段

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | u32 | 本节点骨干 ID，非 0，必须出现在 `members` 中 |
| `region` | string | 区域 ID 规则；必须等于 `members` 中本节点一项的区域；同一请求体的 `networks` 中必须有 `tag` 为 `mesh-<region>` 的网络，它就是本区域网络 |
| `members` | array | 2–256 项；`id` 不重复；每个区域至少一项。区域少于 2 个边界节点时只告警（规格 §15.6 要求每区域至少 2 个，属部署要求） |
| `members[].link` | object | `kind` 为已注册的骨干链路实现名，`params` 原样交给实现；本节点一项的 `link` 是本端监听参数 |

`kind` 未注册（开源构建没有任何实现）时，`backbone` 不运行，状态给出 `failure.code = backbone_kind_unavailable`，本区域网络照常运行；这不算请求无效。字段缺失、未知字段或违反上表约束时，整个请求体返回 400，不应用（与 `networks` 相同）。

**链路参数的保密**：`members[].link.params` 由链路实现解释，可能含密钥、证书或私钥。

- 其中的密钥部分与 `network.secret` 一样，由 Agent 从钥匙串（或节点的密钥存储）注入后下发，不写进面板保存的配置正文。
- `params` 不出现在任何应答、状态、事件、错误信息和日志中。错误信息只指出字段路径（例如 `backbone.members[3].link.params`）和违反的规则，不回显取值；链路实现返回的错误也按此处理后再上报。

### B.2 额外网段

`extra_prefixes`：面板配置的额外汇总网段（规格 §17.3.3 字段 4 第三类），最多 256 项，规则同 A.2 的 prefixes。

### B.3 区域策略

- `deny_link`：禁止互连的区域对列表，每项两个不同的区域 ID，无序，最多 256 项。见 A.6 第 3 条与规格 §17.3.5 第 3 步。
- `preferred_transit`：`源区域 → [中转区域]`。从源区域的入口出发、经列表中区域的中转路径，代价乘以 0.8（规格 §17.3.5 第 3 步）。
- 默认值（面板为四个默认区域生成）：`deny_link = [[cn, eu], [cn, na]]`，`preferred_transit = { cn: [ap] }`，即规格 §17.3.5 第 5 步。
- 两个字段中出现的区域 ID 不必已在 `members` 中（区域可以后加），但必须符合区域 ID 规则。

### B.4 跨区访问控制

- `access`：规则列表，最多 1024 项。每条规则 `from`、`to` 各为 1–64 个 CIDR。
- 入口节点对每个要发往骨干的包，检查是否存在一条规则，其 `from` 有一项包含源 IP、`to` 有一项包含目的 IP。存在则允许，否则拒绝。
- 规则有方向。回程包由对方区域的入口按其自己的规则检查，因此双向互通要两侧各配一条。
- 列表为空表示拒绝所有跨区流量（规格 §15.6 第 7 条默认拒绝）。

### B.5 速率

`limits.ip_pps`、`limits.ip_bps`：每条链路接收 IP 包的速率上限，0 表示链路实现的默认值。直接写入 A.8 的接收策略。

## C. 骨干的状态与事件

### C.1 状态

`GET /v1/mesh`（以及 `PUT /v1/mesh` 的应答）的顶层，与 `networks` 同级，增加 `backbone` 对象；本节点不是边界节点时为 `null`。字段名与 `GET /v1/mesh` 其余字段一样用下划线：

| 字段 | 内容 |
| --- | --- |
| `id`、`region` | 本节点骨干 ID 与区域 |
| `running`、`failure` | 骨干是否在运行；`failure` 为 `null` 或 `{ "code", "detail" }`，`code` 如 `backbone_kind_unavailable` |
| `links[]` | 每个成员一项：`peer`、`region`、`up`、`forward_secrecy`、`transport`、`rtt_ms`、`loss_ppm`、`jitter_ms`、`cost`（无穷大时为 `null`）、`usable`（满足 A.6 第 1 条且已稳定 10 秒） |
| `regions[]` | 每个已知区域一项：`region`、`prefixes`、`borders[]`（`id`、`reachable`、`expires_in_s`） |
| `routes[]` | 每个其他区域的汇总网段一项：`prefix`、`region`、`egress`、`via`（经中转时为中转节点 ID，直达为 null）、`cost`、`since`（本路径选定的时间） |
| `withdrawn` | bool：本节点当前是否因与骨干全部失联而撤回了汇总网段（规格 §15.6 第 6 条） |
| `counters` | 丢弃计数：`no_route`、`access`、`relay_unreachable`、`inconsistent`、`not_for_us`、`bad_message`、`unknown_type`、`link_send` |
| `alerts[]` | 当前未撤销的告警 `{ "code", "peer", "detail" }`，`code` 见 C.2；不适用时 `peer` 为 0、`detail` 为空串 |

状态中不出现链路参数（`params`）、密钥或证书。Agent 把 `backbone` 原样随节点状态上报面板。

### C.2 切换事件

每次路径切换（规格 §17.3.5）产生一条事件，经组网状态的事件队列上报 agent：

| 字段 | 内容 |
| --- | --- |
| `kind` | `backbone_route_changed` |
| `prefix`、`region` | 目的网段与区域 |
| `from`、`to` | 旧路径与新路径，各为 `{egress, via}`；首次选路时 `from` 为 null |
| `reason` | `initial`、`latency`、`loss`、`congestion`、`down`、`recovered`、`relay_unreachable`、`policy` 之一 |

同一目的网段的事件按规格 §17.3.5 的切换间隔自然限速；所有事件合计每秒至多 50 条，超出只计数。

告警（进入 C.1 的 `alerts[]`，并作为事件上报一次）：

| `kind` | 触发 | 撤销 |
| --- | --- | --- |
| `backbone_link_insecure` | 某条链路报告当前会话不具备前向保密（A.6 第 1 条） | 该链路恢复前向保密 |
| `backbone_forward_inconsistent` | A.7 第 2 步丢弃 | 5 分钟内未再发生 |
| `backbone_prefix_conflict` | A.2 接收规则第 3 条，或不同区域通告重叠前缀 | 冲突的通告作废或改正 |
| `backbone_seq_duplicate` | A.1 序号相同、内容不同 | 5 分钟内未再发生 |
| `backbone_region_unreachable` | 某个其他区域的所有汇总网段都没有可用路径 | 该区域重新有可用路径 |
